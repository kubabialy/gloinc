Get started

This guide covers the proposed 0.1.0 feature boundary. It is a release candidate, not a published release. Linux acceptance on ARM64 and x86_64 is required before 0.1.0 can ship. Ubuntu ARM64 passed the local core, complete-suite classification, and installed/relocated package gates; hosted x86_64 CI remains. For the published 0.0.4 compiler, use its numbered guide. Work through the programs in order: write a source file, check it, run it, then build a native executable. The later sections explain values, arrays, slices, vectors, generics, enums, control flow, structs, pointers, raw memory, results, imports, input, and networking. Links at the end give full API contracts.

On Apple Silicon macOS, install Xcode Command Line Tools, CMake 3.28+, Ninja, and LLVM/MLIR 21.1.6. From a source checkout:

bash scripts/install-llvm.sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DLLVM_DIR=/opt/homebrew/opt/llvm/lib/cmake/llvm \
  -DMLIR_DIR=/opt/homebrew/opt/llvm/lib/cmake/mlir
cmake --build build -j 2

On Ubuntu 24.04 ARM64 or x86_64, install CMake 3.28+, Ninja, a C++23 compiler, and the shared LLVM/MLIR 21.1.8 packages:

sudo apt-get update
sudo apt-get install -y cmake ninja-build g++ python3
bash scripts/install-llvm-linux.sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DLLVM_DIR=/usr/lib/llvm-21/lib/cmake/llvm \
  -DMLIR_DIR=/usr/lib/llvm-21/lib/cmake/mlir
cmake --build build -j 2

Install with cmake --install build --prefix "$HOME/.local" if you want a reusable compiler and standard modules. A packaged gloinc needs the matching platform toolchain to start: LLVM/MLIR 21.1.6 on macOS or 21.1.8 on Ubuntu. The archive does not bundle it. Run the matching install-llvm.sh or install-llvm-linux.sh under share/gloinc/scripts/ before invoking bin/gloinc. Executables produced by Gloin do not need LLVM at runtime.

Save this as hello.gloin:

    std.println("Hello World!");
    return 0;
}
./build/gloinc --check hello.gloin
./build/gloinc --jit hello.gloin
./build/gloinc hello.gloin
./a.out
./build/gloinc -o hello hello.gloin
./hello

Compiler and native output

Run the following commands from the directory containing your source file. By default, the compiler builds a standalone executable for the current supported host named a.out; use -o PATH to choose its name. --jit or its alias --run executes the source immediately. --check validates a file without running it.

gloinc [--jit | --run | --check | --emit-ir | --emit-llvm | --emit-object | --emit-exe] \
       [-O0 | -O2] [-o PATH] [--stdlib-dir DIR] [--] FILE [-- ARG...]
gloinc --help
gloinc --version
ModeBehavior
default / --emit-exeLink a standalone host executable with the static Gloin runtime. Output is a.out unless -o PATH is supplied. Pass arguments directly to the executable.
--jit / --runJIT runs main() -> i32. Its low eight bits become the compiler process exit status. A program returning 42 exits with status 42; that alone does not print 42. Use FILE -- ARG... for program arguments.
--checkParse, type check, and verify without running. Main is optional.
--emit-ir, --emit-llvmPrint verified high level or LLVM dialect MLIR for inspection.
--emit-object -o PATHWrite a native object with a process entry point. Link it with libgloin_runtime.a using the pinned clang++.
--emit-exeExplicit spelling for the default executable mode.

Native object and executable output default to -O0. Add -O2 to run LLVM's O2 IR pipeline before native code generation, for example gloinc -O2 -o hello hello.gloin. Optimization flags apply only to native output, not JIT or inspection modes. They do not change the language's checked arithmetic and pointer rules. Source, output, and link errors go to stderr and exit 1. Usage errors exit 2. Successful checks and emission exit 0. Runtime arithmetic traps terminate the program. Quote paths with spaces. --stdlib-dir DIR selects a directory of @ modules. The compiler reports source locations for rejected code.

Source and declarations

Source is UTF-8; identifiers use ASCII letters, digits, and underscores. Comments start with //. Bindings, assignments, call statements, returns, imports, and defer statements end in ;. Function and control flow bodies use braces with no trailing semicolon. Declarations start with def; pub or priv follows def, with private as the default across modules.

def const LIMIT: i32 = 42;
def pub calculate(x: i32) -> i32 { return x + LIMIT; }
// Inside a function:
def count: i32 = 0;      // Binding cannot be reassigned.
def mut total: i32 = 0;  // Binding can be reassigned.
total = total + count;

All bindings, parameters, fields, and return types need explicit types. A local may be declared without an initializer, then assigned before use. def const defines a compile time value; its expression cannot call a runtime function. Names in an inner block can shadow outer names. Assignments are statements, not expressions. There are no implicit numeric conversions or overloads.

Integer literals accept decimal, 0x hexadecimal, and 0b binary spelling. Floating literals use decimal spelling and a type context. The context of a binding, parameter, field, or return can select a literal's type. Gloin does not implicitly convert one typed numeric value to another.

Expressions have unary - and !; arithmetic + - * / % (remainder is integer only); comparisons == != < <= > >=; and boolean && ||. Parentheses control grouping. Arithmetic binds before comparisons, and comparisons before boolean operators. && and || short circuit; other operands and call arguments evaluate left to right. Integer overflow, division by zero, and non-finite floating results trap at runtime; invalid constant expressions fail during checking.

Fixed arrays

A fixed array has an element type and a length known when you compile. Write its type as [T; N] and initialize it with exactly N values in braces. Indexes start at zero. This complete program prints sum = 42:

import "@std";

def sum(values: [i32; 4]) -> i32 {
    def mut total: i32 = 0;
    for def mut i: usize = 0; i < 4; i = i + 1 {
        total = total + values[i];
    }
    return total;
}

def main() -> i32 {
    def mut values: [i32; 4] = {8, 13, 7, 10};
    values[3] = 14;
    if sum(values) != 42 { return 1; }
    std.println("sum = 42");
    return 0;
}

An array is a value: assigning it, passing it to a function, or returning it copies its elements. [i32; 2] and [i32; 3] are different types. An array literal needs a type context from a binding, parameter, field, or return; [1, 2] is not an array literal. Nested arrays use nested braces, such as def grid: [[i32; 2]; 2] = {{1, 2}, {3, 4}};. Empty arrays use [i32; 0] = {}.

Every indexed read or write checks 0 <= index < N and traps on failure, including any access to a zero-length array. Writing an element requires writable storage. &values[0] borrows a live element; it does not extend that element's lifetime. A pointer to an array points to the whole array, not its first element. Fixed arrays support checked slice ranges such as values[1..3]. A nullable pointer to an element can use signed element offsets; pointer offsets do not carry the array's bounds check. A declared array may use zeroed when its element type has a zero value: integer 0, float 0.0, false, null nullable pointer, empty string, or recursively zeroed nested array. It still allocates its full storage. {value; N} evaluates one value and copies it into all N elements. Arrays of non-null references, structs, and enums cannot use zeroed. See the detailed guide and the packaged fixed_arrays.gloin example.

Borrowed slices and vectors

A [T] slice is a pointer and length view of existing contiguous storage. It does not own or copy elements. A writable array can produce values[..], values[1..], or values[1..3]; the end is exclusive. The same ranges work on slices. The compiler checks range and index bounds. .len is a read-only u64. A [const T] slice permits reads only. Keep the underlying array or arena alive while using a slice.

def main() -> i32 {
    def mut values: [i32; 4] = {1, 2, 3, 4};
    def middle: [i32] = values[1..3];
    middle[0] = 20;
    return values[1] + middle[1]; // 23
}

Import @vector to use one of two vector types. vector.Vector<T; N> stores N initialized slots inline and a logical length. It has no arena allocation; push returns false when full. vector.Vector<T> stores elements in a caller-owned GeneralArena and grows its capacity when pushed. Use Vector<T>.empty(&memory, capacity) to reserve uninitialized spare slots, including for struct or enum elements with no zero value. The older create(&memory, capacity, fill) remains available; it evaluates but no longer stores the fill value in spare slots. Both forms provide len(), cap(), push(value), get(index), get_mut(index), and clear(). Get methods return nullable pointers; check for null before dereferencing.

import "@vector";

def main() -> i32 {
    def mut values: vector.Vector<i32; 2> = vector.Vector<i32; 2>.create(0);
    if !values.push(20) || !values.push(22) { return 1; }
    if values.push(99) { return 2; }
    def first: *const i32 = values.get(0);
    if first == null { return 3; }
    return *first + 22;
}

For a growable vector, create an arena and call vector.Vector<i32>.empty(&memory, 2). Growth allocates a new buffer in that arena. Both vector forms now support as_slice() and as_const_slice() over live elements, plus append_from, insert, remove, truncate, and pop. The growable form also supports reserve. A view captures the current length; it never exposes spare capacity. Treat pointers and views as invalid after growth or a moving reserve; arena reset/free invalidates all arena vector storage. Copying a growable vector copies its descriptor, so copies can disagree about length and capacity. Copying a fixed vector copies its entire inline buffer. @slices adds generic fill, reverse, and nonoverlapping copy helpers. See the ownership and API guide and packaged examples.

Generics and enums

Generic structs, functions, and methods use explicit type arguments. A generic struct can also take a compile-time size parameter after a semicolon. The size becomes part of its type and layout; it may size a fixed array field. The compiler specializes checked bodies for concrete arguments. There is no inference for generic function or method calls.

def struct Box<T> {
    def pub value: T,
    def pub static create(value: T) -> Box<T> {
        return Box<T> { value: value };
    }
}

def identity<T>(value: T) -> T { return value; }

def main() -> i32 {
    def box: Box<i32> = Box<i32>.create(42);
    return identity<i32>(box.value);
}

A type such as Buffer<i32; 16> supplies one type and one compile-time capacity. A method may declare its own type parameters and is called with explicit arguments, for example pair.with_third<bool>(true). See the generic rules and limits.

Enums currently carry no payload. Declare def enum Direction { North, East, South, West }, construct Direction.North, and compare variants of the same enum with == or !=. Export with def pub enum across modules. There is no match expression, variant payload, integer conversion, or guaranteed foreign ABI. See the enum guide.

Functions and control flow

Functions declare the type of every parameter and an explicit return type. The root source file needs def main() -> i32 to run or emit native output. Other functions may return void. This program returns 42 as its exit status:

def add(a: i32, b: i32) -> i32 { return a + b; }
def main() -> i32 {
    def mut total: i32 = 0;
    for def mut i: i32 = 0; i < 3; i = i + 1 {
        if i == 1 { total = add(total, 20); }
        else { total = add(total, 11); }
    }
    return total;
}

Use if/else, unless (run a body when its condition is false), while, and C style for with braced bodies. break and continue are not part of this release. Functions may call later declarations and recurse. A non-void function must return a value on every reachable path. An early return exits the function.

defer call(...); schedules a function call for normal function exit. Its arguments are evaluated and captured when execution reaches the defer; deferred calls run in reverse registration order. A runtime trap does not run them. Use this for cleanup such as defer memory.free();.

Structs and methods

A struct groups named, typed fields. Struct values copy by value. Separate a struct's fields with commas and construct a value with every required field. A field can be reassigned only if its declaration uses def mut. Methods declare a typed self parameter; static methods have no self. This complete program also returns 42:

def struct Counter {
    def mut value: i32,
    def static make(value: i32) -> Counter {
        return Counter { value: value };
    }
    def add(self: &Counter, amount: i32) -> void {
        self.value = self.value + amount;
    }
    def read(self: &const Counter) -> i32 { return self.value; }
}

def main() -> i32 {
    def mut counter: Counter = Counter.make(40);
    counter.add(2);
    return counter.read();
}

Inside its declaring module, a method can read private fields. Other modules can use only pub members. A method receiver may be a struct value, reference, or pointer of the declared kind. The compiler checks whether writes through self are allowed. Recursive structures use pointer or reference fields; by-value recursive layout is rejected.

Pointers, references, and &*p

Gloin makes nullability visible in the type. *T is a pointer that may hold null. &T is a reference to an existing initialized T and cannot be null. Adding const after * or & makes the pointee read-only. Neither form allocates or owns memory.

SourceMeaning
def mut x: i32 = 41;
def r: &i32 = &x;		&x takes the address of an initialized, writable place. r cannot be rebound, but *r = 42; can change x.
def mut p: *i32 = r;A non-null reference can weaken to a nullable pointer. The reverse conversion is never implicit.
if p != null { add_one(&*p); }&*p is an expression: dereference p, check it for null, and create a non-null reference. If p is null, evaluation traps. The check does not prove the storage is still alive.
def slot: &*i32 = &p;&*i32 is a type: a non-null reference to a nullable *i32 variable. It is not a nullable reference. *slot = null; changes the pointer stored in p.

The same characters mean different things in a type and in an expression: &*i32 nests the reference and pointer types, while &*p takes a reference through the pointer value named p. There is no nullable reference type in the current language. Use *T for an optional address, and &*T when a function needs to rebind an existing optional pointer slot.

This complete program exercises both forms and returns 42. set_slot receives a non-null reference to the nullable pointer variable. add_one receives a non-null reference to the integer behind that pointer.

def add_one(value: &i32) -> void { *value = *value + 1; }
def set_slot(slot: &*i32, value: *i32) -> void { *slot = value; }

def main() -> i32 {
    def mut answer: i32 = 41;
    def reference: &i32 = &answer;
    def mut pointer: *i32 = null;
    set_slot(&pointer, reference);
    if pointer == null { return 1; }
    add_one(&*pointer);
    return answer;
}

Dereferencing a null pointer, using p.field when p is null, or evaluating &*p when p is null traps. null needs a pointer type from context; it cannot initialize &T. A pointer is not a boolean: compare it with null. Pointer comparisons compare addresses, not values. There is no arbitrary pointer cast.

A nullable data pointer *T can advance by a signed i64 number of elements: p + offset. This complete program returns 32:

def main() -> i32 {
    def mut values: [i32; 3] = {10, 20, 12};
    def first: *i32 = &values[0];
    def second: *i32 = first + 1;
    return *second + *(second + 1);
}

Run the packaged pointer_offsets.gloin with gloinc --jit, or build it with gloinc -O2 -o pointer-offsets pointer_offsets.gloin. Adding any offset to null traps, including zero. Pointer offsets do not check allocation bounds: keep both addresses within the same live allocation or one past its end, and never dereference one past. &T, void and function pointers cannot be offset; pointer subtraction, ordering, and indexing remain unsupported. Fixed-array indexing retains its runtime bounds check. See the full pointer-offset contract.

Only the outer pointer layer may weaken from writable to read-only or from reference to pointer. Binding mutability and pointee mutability differ: def p: &i32 cannot rebind p but can write *p; def mut p: *const i32 can rebind p but cannot write *p. You may take an address only of initialized, addressable storage, not a literal or temporary.

Memory management is manual. Gloin has no borrow checker or lifetime tracking. A reference must still point to live storage after a null check; copying or returning an address does not extend the value's life. @arena provides GeneralArena for initialized typed allocation. reset() invalidates all values in that arena while retaining blocks; free() releases them. See the arena guide for allocation and failure behavior.

Raw memory and custom arenas

Import @memory when a custom allocator needs an individual native block. memory.alloc(bytes, alignment) returns a nullable *u8 over uninitialized bytes; invalid sizes or alignment and allocation failure return null. memory.free(pointer) accepts null, or the original pointer returned by alloc exactly once. size_of<T>(), align_of<T>(), and padding<T>(pointer) expose target layout. place<T>(pointer, available, value) checks null, alignment, and the stated available byte count, then writes a copy of the value and returns *T; failure returns null without writing.

import "@memory";

def main() -> i32 {
    def block: *u8 = memory.alloc(64, 16);
    if block == null { return 1; }
    defer memory.free(block);
    def number: *i32 = memory.place<i32>(block, 64, 42);
    if number == null { return 2; }
    return *number;
}

The caller must provide the true remaining writable byte count, keep the block live, and never read uninitialized bytes. free does not destroy placed values; pointers into the block become invalid after free. Runtime traps do not run defers. See the raw memory contract and the packaged custom_arena.gloin example for a complete bump arena.

Results and errors

result<T> and error are built-in lowercase types and reserved words in this 0.1.0 candidate. Source that used either as an identifier in 0.0.4 must rename it. A result<T> holds exactly one success value or one error. result<void> allows a success without a value; result<error> is invalid. Returning a T or an error from a function declared result<T> wraps that branch automatically. An error is constructed from one string literal, for example error("invalid input"). Its read-only .message is a static Gloin string.

import "@std";

def increment(text: string) -> result<i32> {
    def number: result<i32> = std.parse_i32_checked(text);
    if number.erroneous { return number.error; }
    return number.value + 1;
}

def main() -> i32 {
    def answer: result<i32> = increment("41");
    if answer.erroneous {
        std.println(answer.error.message);
        return 1;
    }
    return answer.value;
}

Every result binding, including a parameter, must be checked with .erroneous on every path that leaves its scope. The compiler permits .value only on a proven success path and .error only on a proven failure path. Direct if r.erroneous, if !r.erroneous, and unless r.erroneous establish proofs; a branch that returns can establish the opposite proof afterward. Reassigning a mutable result requires a new check. A result call cannot be discarded. Propagation is explicit: return the checked .error; a whole result cannot be returned directly.

Errors currently contain a static message only. They have no source location, stack trace, or debug payload. Results cannot currently be stored as struct fields or behind pointers, arrays, or slices; access requires a named binding. A successful pointer or borrowed string payload keeps its ordinary lifetime rules. The complete result contract explains flow checks and GloinIR lowering. The packaged result_handling.gloin example demonstrates success and forwarding.

Modules

Put these two files in one directory. The imported file gives an ordinary function public visibility. The root file calls it through the module name:

guide_utils.gloin

def pub twice(x: i32) -> i32 { return x + x; }

main.gloin

import "./guide_utils";

def main() -> i32 { return guide_utils.twice(21); }

gloinc --jit main.gloin exits with status 42; gloinc main.gloin writes a.out. @name loads name.gloin from the standard library directory. Relative imports resolve from the importing source file; you can include or omit the .gloin extension. A module exposes its pub functions, constants, and structs through its namespace. Only the root file supplies main; imports have no runtime initialization. Import cycles, missing files, and private access produce diagnostics.

Input and standard library

Standard modules use the same import and namespace rules. Output is explicit: a return value sets the exit status but does not print. std.print writes bytes without a newline and std.println adds one. std.input returns a status-bearing struct because EOF is a normal outcome; checked parsing returns result<i32> for invalid text or overflow. This program reads a decimal integer, adds one, and prints it. Try printf '41\n' | gloinc --jit next.gloin.

import "@std";
import "@arena";

def main() -> i32 {
    def mut memory: arena.GeneralArena = arena.GeneralArena.create();
    defer memory.free();
    def line: std.InputResult = std.input(&memory, 64);
    if line.status != std.OK { return 1; }
    def parsed: result<i32> = std.parse_i32_checked(line.value);
    if parsed.erroneous {
        std.println(parsed.error.message);
        return 2;
    }
    std.println(std.to_string(&memory, parsed.value + 1));
    return 0;
}

line.value borrows bytes owned by memory. Use it before memory.reset() or memory.free(). The example treats every non-OK input status as exit 1; a larger program can distinguish std.END, std.NO_MEMORY, and other errors. std.to_int remains available with its status struct. The standard library guide lists the exact statuses and signatures.

Nonblocking TCP and HTTP

The 0.1.0 candidate adds @net for IPv4 TCP and @http for bounded HTTP/1.1 request and response heads. Socket operations return built-in result<T>; inspect .erroneous before reading a success value. Ordinary network states stay in the success payload: a pending connection is false, an unavailable accept has available == false, a read can report status.WOULD_BLOCK or status.END, and a timed readiness wait returns zero bits. Socket copies share ownership state, so close a socket before freeing its arena.

import "@arena";
import "@net";

def cleanup(socket: &net.Socket) -> void {
    if !socket.is_open() { return; }
    def closed: result<void> = socket.close();
    if closed.erroneous { return; }
}

def main() -> i32 {
    def mut owner: arena.GeneralArena = arena.GeneralArena.create();
    defer owner.free();
    def opened: result<net.Socket> = net.Socket.open(&owner);
    if opened.erroneous { return 1; }
    def mut socket: net.Socket = opened.value;
    defer cleanup(&socket);
    def started: result<bool> = socket.connect(net.Address.loopback(8080));
    if started.erroneous { return 2; }
    if !started.value {
        def ready: result<i32> = socket.wait(net.WRITABLE, 1000);
        if ready.erroneous { return 3; }
        if ready.value == 0 { return 4; }
        def finished: result<bool> = socket.finish_connect();
        if finished.erroneous { return 5; }
        if !finished.value { return 6; }
    }
    def closed: result<void> = socket.close();
    if closed.erroneous { return 7; }
    return 0;
}

This sketch expects a listener on localhost:8080; its deferred cleanup closes the socket before freeing its arena. The packaged network_http.gloin example creates its own listener, cleans up on every path, and completes a local HTTP exchange. It is runnable with gloinc --jit examples/network_http.gloin or as a native executable.

Socket.read([u8]) and write([const u8])/write_text(string) each make one nonblocking call. Check the returned byte count and retry after readiness; a successful write may be short. strings.view_bytes(buffer[0..count]) borrows received bytes as counted text. Pass that view to http.parse_request or http.parse_response, append more bytes while the successful payload has complete == false, then use header_bytes to locate the body. http.frame_request and http.frame_response report when a bounded fixed-length body is complete and return its borrowed view. http.format_get and http.format_response build heads in a caller-owned arena and return result<string>. Transfer-Encoding, TLS, DNS, IPv6, UDP, and full HTTP body handling are not yet supplied. The networking guide gives the exact ownership, framing, and error rules.

Support and limits

The 0.1.0 candidate targets Apple Silicon macOS and Ubuntu 24.04 Linux on ARM64 and x86_64. Ubuntu ARM64 has passed local core, complete-suite, and package acceptance; hosted x86_64 CI remains a release gate. Windows support is not planned; contributions are welcome. Cross compilation and Intel macOS are outside the validated target. Maps, enum payloads and pattern matching, packed bitfields, external packages, and concurrency remain future work. Results currently require direct checks on named bindings, and errors contain static messages only.

Native objects and executables target the current supported host. Executables do not need LLVM at runtime. The compiler and native linking step require the pinned toolchain. Objects require the static Gloin runtime at link time.
